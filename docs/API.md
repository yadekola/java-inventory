# API reference

Frontend proxy base: http://localhost:8080/api. Direct base: http://localhost:8080/api. Send application/json for POST and PUT. No authentication is implemented. Use paths without trailing slashes.

| Method | Path | Purpose | Success |
|---|---|---|---|
| GET | /api | Application information | 200 |
| GET | /api/products | List/search/filter products | 200 |
| POST | /api/products | Create product | 201 |
| GET | /api/products/{id} | Read product | 200 |
| PUT | /api/products/{id} | Replace all five editable fields | 200 |
| DELETE | /api/products/{id} | Delete product | 204, empty body |
| GET | /actuator/health | Overall health, direct API port | 200 or 503 |
| GET | /actuator/health/readiness | Application readiness plus DB | 200 or 503 |
| GET | /actuator/health/liveness | Application liveness | 200 or 503 |

PATCH is not implemented. The frontend sends PUT for edits. There is no Swagger UI or OpenAPI endpoint in this edition.

## Product fields

| Field | Type | Rules |
|---|---|---|
| id | integer | Generated, read-only |
| sku | string | Required, max 40; letters/digits/underscore/hyphen, starts with letter/digit; normalized uppercase and unique |
| name | string | Required, nonblank, max 160 |
| category | string | Required, nonblank, max 80 |
| price_minor | integer | Required, 0 to 1,000,000,000 kobo |
| quantity | integer | Required, 0 to 1,000,000,000 |
| created_at | timestamp | Generated by database |
| updated_at | timestamp | Updated by API writes |

POST/PUT require all five editable fields. Do not send id or timestamps. Unknown fields, fractional integer fields and numeric strings are rejected. Names/categories are trimmed. SKU spaces are invalid. Prices use kobo: 1850000 represents NGN 18,500.00.

Request example:

```json
{"sku":"KB-001","name":"Wireless keyboard","category":"Accessories","price_minor":1850000,"quantity":24}
```

Single product responses wrap the product in `data`:

```json
{"data":{"id":1,"sku":"KB-001","name":"Wireless keyboard","category":"Accessories","price_minor":1850000,"quantity":24,"created_at":"2026-10-11T12:00:00Z","updated_at":"2026-10-11T12:00:00Z"}}
```

IDs and timestamps above are illustrative. POST includes a Location header.

List: `/api/products?page=1&limit=10&search=keyboard&category=Accessories`. Page defaults to 1 and accepts 1 through 1,000,000. Limit defaults to 10 and accepts 1 through 100. Search is case-insensitive on name/SKU, up to 160 characters. Category is exact and case-sensitive, up to 80 characters. `%` and `_` act as SQL search wildcards. All values are passed as SQL parameters.

```json
{"data":[],"pagination":{"page":1,"limit":10,"total":0,"total_pages":0}}
```

Results are newest ID first. Pages beyond the end return an empty array. Count and list queries are separate, so concurrent writes can briefly change their agreement. Updates use last-write-wins behavior.

## Errors

400: invalid fields, JSON, ID or pagination. 404: missing product. 409: duplicate SKU or database constraint conflict. 405: unsupported method. 415: unsupported request media type. Unexpected infrastructure faults return Spring Boot's standard error response; controller validation errors use the structure below. Unknown routes may also use the standard Spring error shape.

```json
{"error":{"code":"VALIDATION_ERROR","message":"Check the submitted fields.","details":{"quantity":"must be greater than or equal to 0"}}}
```

Validation messages use Java field names, so `priceMinor` may appear in details for the JSON field `price_minor`.

## PowerShell example

```powershell
$base = 'http://localhost:8080/api'
$body = @{sku='DEMO-001'; name='USB hub'; category='Accessories'; price_minor=350000; quantity=5} | ConvertTo-Json
$p = Invoke-RestMethod "$base/products" -Method Post -ContentType 'application/json' -Body $body
$id = $p.data.id
Invoke-RestMethod "$base/products/$id"
$updated = @{sku='DEMO-001'; name='USB hub'; category='Accessories'; price_minor=350000; quantity=10} | ConvertTo-Json
Invoke-RestMethod "$base/products/$id" -Method Put -ContentType 'application/json' -Body $updated
Invoke-RestMethod "$base/products?search=hub"
Invoke-RestMethod "$base/products/$id" -Method Delete
```

## curl example (Linux/macOS)

```bash
curl http://localhost:8080/actuator/health/readiness
curl -i -X POST http://localhost:8080/api/products -H 'Content-Type: application/json' -d '{"sku":"DEMO-001","name":"USB hub","category":"Accessories","price_minor":350000,"quantity":5}'
# Replace 1 with the returned ID.
curl http://localhost:8080/api/products/1
curl -i -X DELETE http://localhost:8080/api/products/1
```
